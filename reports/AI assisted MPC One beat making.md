# Let the PC build kits; you play pads

The Akai MPC One cannot be scripted from the inside, so the only architecture that works is to treat it as a closed, standalone instrument and put every piece of AI-driven automation on the Windows 11 PC, communicating through three channels the MPC does expose: files on an SD card (samples and `.xpm` programs going in, exported audio tracks and MIDI coming out), MIDI/clock over the 5-pin ports or USB, and the stereo analog outputs into an audio interface. Within that frame, almost the entire pipeline can be assembled from open-source, pip-installable tools that Claude Code can write and drive: **`audio-separator` and DrumSep for stems, librosa/soundfile for transient chopping, a small custom XML writer (or `mpc-keygroup-builder`/ConvertWithMoss) for drum and keygroup programs, a DAW with a Model Context Protocol server for capture and arrangement, `allin1` for section detection, Pedalboard plus Airwindows/LSP plugins for scripted mixing, and Matchering for reference-based mastering**. The one place open source falls short is the DAW itself: Ardour 9 is the only production-ready FOSS DAW on Windows and ships an official MCP server, but REAPER ($60, proprietary) has far richer agent tooling, including loudness measurement, and is the pragmatic recommendation. Custom instruments are possible but indirect: an AI-built VST3 (JUCE via the MIT-licensed Audio Plugin Coder) can only sound on the MPC One after being multisampled into a keygroup program, either with Akai's Auto Sampler in controller mode or headlessly with Pedalboard/DawDreamer. The hard constraints are the One's 2 GB RAM, its inability to stream multitrack audio over USB while standalone, the mutual exclusivity of controller mode and standalone operation, the lack of Wi-Fi, and the under-documented MPC 3 project format, which is why the design below keeps the MPC on SD-card-delivered programs and never tries to write its project files.

## The MPC One is a closed box with three doors

Everything about the design follows from what the original MPC One (2020) is and is not. It is a current, fully supported MPC 3 device: **MPC OS 3.10, released 22 October 2026, is free for all standalone MPCs**, and the One has received every 3.x release from 3.4 through 3.10 ([Synth Anatomy](https://synthanatomy.com/2026/10/akai-mpc-os-3-10-free-feature-update-for-mpc-standalone-force-mpc-3-desktop.html); [Akai MPC3 FAQ](https://support.akaipro.com/en/support/solutions/articles/69000857771-mpc3-faq)). That means the One has MPC 3's linear Arrange mode, the one-to-one track architecture, disk streaming, the $9.99 four-stem MPC Stems add-on, and since 3.9 built-in oscillators on drum and keygroup tracks ([Synth Anatomy 3.9](https://synthanatomy.com/2026/06/akai-mpc-3-9-os-turns-the-standalone-mpcs-and-force-into-a-full-synthesizer.html); [DJ Mag](https://djmag.com/tech/akai-unveils-stem-separation-legendary-sampler-mpc-stems)). What it lacks is hardware: **a 1.8 GHz quad-core CPU, 2 GB RAM, 4 GB storage (2 GB free), 8 standalone audio tracks, 24-bit/44.1 kHz max, one stereo line in and one stereo line out, no Wi-Fi, no Bluetooth** ([Akai MPC One FAQ](https://support.akaipro.com/en/support/solutions/articles/69000816149-akai-pro-mpc-one-frequently-asked-questions); [Sound On Sound](https://www.soundonsound.com/reviews/akai-mpc-one)). Forum users on 2 GB units report heavy plugins such as Fabric stalling at preset load and resource pressure in general, which is anecdotal but consistent with the spec sheet ([Dubspot](https://blog.dubspot.com/akai-mpc-buyers-guide-2026); [MPC-Forums](https://www.mpc-forums.com/viewtopic.php?p=1875905)). The practical rule for kit building is therefore trimmed 16-bit/44.1 kHz one-shots and modest sample counts.

The first and most important wall is that **no third-party plugin can run on the MPC One in standalone mode**. Akai states it is "not possible to load/install additional 3rd party plugins into the MPC in Standalone mode"; only AIR, Akai, Native Instruments and Spitfire titles activated under Preferences > Activations are available, and a project with a third-party plugin track will play MIDI with no sound, for which Akai's suggested fix is converting the sound into a keygroup with Auto Sampler ([Akai: 3rd party VSTs](https://support.akaipro.com/en/support/solutions/articles/69000876025-akai-mpc-series-how-to-use-3rd-party-vst-s-with-your-mpc); [Akai: plugin instruments missing](https://support.akaipro.com/support/solutions/articles/69000855034-akai-pro-mpc-series-plugin-instruments-missing-in-project-)). VST3 plugins run only in Controller Mode, where the hardware becomes a surface for MPC 3 Desktop on the PC, "standalone functionality is disabled" and the internal drive is inaccessible ([Akai: stuck on 'Looking for computer'](https://support.akaipro.com/en/support/solutions/articles/69000837366-akai-pro-mpc-series-why-is-my-mpc-stuck-on-looking-for-computer-); [Akai MPC One FAQ](https://support.akaipro.com/en/support/solutions/articles/69000816149-akai-pro-mpc-one-frequently-asked-questions)). Reverse engineering of the sibling MPC Live confirms why: it is a Buildroot Linux box running a closed JUCE application, and controller mode literally flips a USB multiplexer so the audio and MIDI hardware attach to the host computer instead of the internal CPU ([MPC Live Internals](https://niklasnisbeth.gitlab.io/mpc-internals/)). There is no API, no SSH, and no custom firmware for the One; the only custom-firmware precedent is for the legacy MPC500 ([Synth Anatomy](https://synthanatomy.com/2026/10/m45k-open500-custom-akai-mpc500-firmware.html)).

The second wall is audio and MIDI transport. Akai lists the One as Windows 11 "Supported" with the 2.10.0.83+ driver package, but no Akai document states the USB audio channel count, and the community consensus is that **a standalone MPC cannot stream its multitrack mix to a DAW over USB**; the hardware has one main codec pair, and the recommended workarounds are analog outs into a multi-input interface, a class-compliant USB interface attached to the MPC, or controller mode with the MPC plugin's multi-outs ([Akai Windows 11 Compatibility](https://support.akaipro.com/en/support/solutions/articles/69000802493-akai-pro-windows-11-compatibility); [MPC-Forums](https://www.mpc-forums.com/viewtopic.php?t=215924&p=1864892); [MPC-Forums](https://www.mpc-forums.com/viewtopic.php?f=48&t=193079)). Akai's own article on using the MPC as a plain USB-MIDI controller for PC plugins while standalone ("Direct USB-MIDI") restricts that feature to the MPC Key 37 and the Gen-2 models, and points every other MPC at the 5-pin MIDI Out plus a USB/MIDI interface ([Akai: 3rd party VSTs](https://support.akaipro.com/en/support/solutions/articles/69000876025-akai-mpc-series-how-to-use-3rd-party-vst-s-with-your-mpc)). The conclusion for the architecture is blunt: the "play standalone, record on PC" path needs a small audio interface with a MIDI input, into which the One's 1/4" outs and 5-pin MIDI Out are patched. The MPC's sync options are MIDI Clock, MTC and Ableton Link, but Link on the original One requires a USB-to-Ethernet adapter and Akai's network driver because there is no Wi-Fi, so MIDI Clock over the 5-pin cable is the low-friction choice ([Akai multi-MIDI control](https://support.akaipro.com/en/support/solutions/articles/69000804431-akai-pro-mpc-series-configuring-midi-ports-for-multi-midi-control); [Akai Link setup](https://support.akaipro.com/en/support/solutions/articles/69000814493-akai-pro-mpc-series-force-ableton-link-setup-and-tutorial)).

The third wall is file formats, and it is the one with the most leverage. Drum and keygroup programs are `.xpm` files with their WAVs beside them, and Akai requires programs and samples to travel together ([Akai: Understanding and Loading Programs](https://support.akaipro.com/en/support/solutions/articles/69000804211-akai-pro-mpc-series-understanding-and-loading-programs)). Community code treats `.xpm` as plain XML (`<Program>` > `<Instruments>` > `<Instrument>`) parsed with `xml.etree`, and a forum merge script in that style worked on MPC One 2.10 and Force 3.1.3 ([MPC-Forums](https://www.mpc-forums.com/viewtopic.php?p=1850940)). MPC 3 projects, by contrast, are **gzip-compressed JSON with a five-line text header, reverse-engineered from only 18 files with the author warning the spec "is likely to contain errors"**, sequences live as undocumented `.sxq` files in the `[ProjectData]` folder, and `.xal` has no public documentation at all ([kurtjcu/MPC-project-file-definitions](https://github.com/kurtjcu/MPC-project-file-definitions); [MPC-Forums](https://www.mpc-forums.com/viewtopic.php?p=1886903)). A May 2026 KVR thread reports that Akai also updated the program file format with a JSON variant of XPM, which is unverified but argues for targeting the classic XML `.xpm` that 3.x still loads ([KVR](https://www.kvraudio.com/forum/viewtopic.php?p=9252901)). Transfer is simplest via SD card (exFAT, up to 2 TB), since the One does not mount USB thumb drives to the desktop in controller mode and the SD slot does ([Akai: transferring content](https://support.akaipro.com/en/support/solutions/articles/69000824436-akai-pro-mpc-series-transferring-content-to-and-from-the-mpc-via-a-computer); [Akai MPC One FAQ](https://support.akaipro.com/en/support/solutions/articles/69000816149-akai-pro-mpc-one-frequently-asked-questions)). Everything below rides on these three doors: SD card files, MIDI, and analog audio.

## Sample prep is fully scriptable except for one 200-line XML writer

The "folder of audio in, playable kit out" stage is the most mature part of the stack, and every component except the program writer is a maintained, MIT/BSD-licensed, Windows-compatible Python package. For stem separation, **`python-audio-separator` (MIT) wraps the UVR model zoo (MDX-Net, VR, Demucs, BS-RoFormer) behind a single CLI, installs with `pip install "audio-separator[gpu]"` or `[cpu]`, and offers an experimental DirectML build for AMD/Intel GPUs on Windows** ([python-audio-separator](https://github.com/nomadkaraoke/python-audio-separator)). Demucs itself remains installable but its repository was archived on 1 January 2025, so the wrapper is the right dependency ([Demucs](https://github.com/facebookresearch/demucs)). Where Akai's $9.99 MPC Stems stops at a single "drums" stem, **DrumSep (MIT) splits a drum stem further into kick, snare, cymbals and toms**, and the `mdxnet-infer` package and MVSep models extend this to six-piece separation, though DrumSep's installer is Linux-oriented and Windows users should expect to install Demucs manually or use WSL2 ([DrumSep](https://github.com/inagoy/drumsep); [MVSep DrumSep](https://mvsep.com/algorithms/29); [mdxnet-infer](https://pypi.org/project/mdxnet-infer/)). UVR5's GUI (MIT, 26.8k stars, Windows installer) is the no-code equivalent for occasional use, with a GTX 1060 6 GB minimum for GPU runs ([UVR](https://github.com/Anjok07/ultimatevocalremovergui)).

For chopping, **librosa 0.11.0 (March 2025, Python 3.12) is the only onset-detection library among librosa, madmom, aubio and Essentia confirmed to install cleanly from wheels on Windows**: Essentia publishes no Windows wheel and is AGPL, and madmom's models are CC BY-NC-SA with a last release in 2018 ([librosa on PyPI](https://simple-repository.app.cern.ch/project/librosa); [Essentia on PyPI](https://pypi.org/project/essentia/); [madmom](https://github.com/CPJKU/madmom)). A Claude Code script using `librosa.onset.onset_detect`, slicing with `soundfile`, trimming silence and normalizing covers what the MPC's own Threshold chop does, and does it in batch over hundreds of files; the MPC still handles the manual version well on-device via Sample Edit > Chop > Shift+Convert > "New Drum Track Using Slices" ([Akai: Convert Chopped Samples](https://support.akaipro.com/support/solutions/articles/69000859300-mpc-series-convert-your-chopped-samples-into-a-drum-program)). Auto-tagging slices as kick/snare/hat has no verified open-source drop-in; a spectral-centroid and decay heuristic, or an LLM-supervised rule set, is the pragmatic fallback.

The program writer is the gap. No open-source tool was found that both chops and writes a drum `.xpm`, and the direct generators are small: BlackCursive/mpckitcreator (Python, SoundFile + BeautifulSoup, 9 stars, no visible license) builds a program from WAVs in a directory, and `smfarrelly/mpc-keygroup-builder` (MIT, Python 3.12, 233 commits, "software-preview") builds pitched keygroups with velocity layers, builds and colours drum programs, audits XPM files, and plans checksum-verified SD deployments for MPC 3 ([mpckitcreator](https://github.com/BlackCursive/mpckitcreator); [mpc-keygroup-builder](https://github.com/smfarrelly/mpc-keygroup-builder)). For keygroups specifically, **ConvertWithMoss (LGPL-3.0, Java, 458 stars, releases through 20.3) lists "Akai MPC Keygroups (*.xpm)" among its formats, has a Windows package and CLI, and a forum user reported SFZ-to-MPC conversion "worked like a charm"** ([ConvertWithMoss](https://github.com/git-moss/ConvertWithMoss); [Mossgrabers.de](https://www.mossgrabers.de/Software/ConvertWithMoss/ConvertWithMoss.html); [MPC-Forums](https://www.mpc-forums.com/viewtopic.php?p=1850195)). The safest engineering approach is the one MPCTK uses for MPC Sample projects: save a known-good program from the MPC on 3.10, treat it as a template, and have the script fill in pad entries while preserving every unknown field ([MPC-Sample-Toolkit](https://github.com/tarikcampos/MPC-Sample-Toolkit)). The MIT-licensed `mpc-preview-builder` then generates the `[Previews]/Name.xpm.wav` files that make kits auditionable in the MPC browser, and a plain folder of `Kit.xpm` plus WAVs on the SD card gives the same browse-and-play result as an `.xpn` expansion without the desktop-software round trip Akai requires for `.xpn` installs ([mpc-preview-builder](https://github.com/Michaelvdlnz/mpc-preview-builder); [Akai: .xpn Expansions](https://support.akaipro.com/en/support/solutions/articles/69000826395-akai-pro-mpc-how-to-install-xpn-expansions)). Commercial shortcuts exist for anyone who wants to skip the writer: Kit Creator ($59.99) and Kit Maker ($35) convert WAV folders to `.xpm`, and MPC Sample Kit Creator converts Maschine and Ableton Drum Rack libraries to 16-pad kits ([KVR](https://kvraudio.com/news/homegrown-sounds-releases-kit-creator-v1-0-58507); [Kit Maker](https://kitmaker.gumroad.com/l/kit-maker); [Ko-fi](https://ko-fi.com/s/409e4308f4)).

Generating new drum sounds with AI is possible but should be done with the license in view. **Stable Audio Open Small (about 0.5B parameters, 11-second 44.1 kHz stereo output) runs on a modest PC and carries the Stability AI Community License, reported as free for commercial use under US$1M revenue**, while MusicGen/AudioCraft weights are CC-BY-NC and therefore unusable for kits you intend to release ([Stable Audio Open Small](https://huggingface.co/stabilityai/stable-audio-open-small); [Stable Audio Open 1.0](https://huggingface.co/stabilityai/stable-audio-open-1.0); [MusicGen README](https://huggingface.co/spaces/civichacker/MusicGen/blob/main/README.md)). No open checkpoint trained specifically for kick/snare one-shots was found; DrumGAN, CRASH and DOSE are research models without public drum weights ([DrumGAN](https://arxiv.org/pdf/2008.12073); [DOSE](https://arxiv.org/pdf/2504.18157)). Among commercial sources, Splice is the clearest: its catalog is royalty-free per download, and its April 2026 Variations and Craft tools are "licensed for commercial use" with creator payouts ([Splice licensing FAQ](https://intercom.help/splice-b7a2d5b83f2e/en/articles/8652642); [Music Business Worldwide](https://www.musicbusinessworldwide.com/splice-launches-ai-tools-that-compensate-sample-creators/)). Use the Splice desktop app and copy to SD rather than the MPC's on-device Splice browser, which needs the Ethernet adapter and has an Akai-confirmed bug where downloaded samples become inaudible ([Akai: Splice samples inaudible](https://support.akaipro.com/en/support/solutions/articles/69000822776-why-can-t-i-hear-my-splice-samples-)).

## REAPER beats Ardour for agent control; Ardour wins on license

The DAW's job in this design is narrow: keep an audio track armed, record the MPC's stereo mix and MIDI, cut the take into sections, hold the plugin chains, measure loudness, and render. Both open-source and proprietary options can do this under LLM control, but they differ sharply in depth. **Ardour 9 (GPL, released 5 February 2026 for Windows) ships an official Model Context Protocol server, "MCPHttp", at `http://127.0.0.1:4820/mcp`**, exposing session, transport, track, send, plugin, marker, region and MIDI tools, with documented client setup for Claude Desktop via `mcp-remote` ([Phoronix](https://phoronix.com/news/ardour-9.0-daw); [Ardour manual: MCP HTTP](https://manual.ardour.org/using-control-surfaces/mcp-http/)). The manual flags it as experimental and notes that edits identify objects by names or IDs that may not be unique, so snapshot before destructive operations. Ardour's Windows binaries are pay-what-you-want with a US$1 minimum or a free demo that goes silent periodically, and building from source on Windows is impractical ([FitGap](https://us.fitgap.com/products/ardour); [Ardour Discourse](https://discourse.ardour.org/t/this-software-is-free/109152)). Zrythm 2.0 and LMMS 1.3 are both alphas as of 2026 with no MCP bridges and should not be the recording host ([Phoronix](https://www.phoronix.com/news/Zrythm-2.0-Alpha); [AlternativeTo](https://alternativeto.net/news/2026/9/lmms-releases-1-3-0-alpha-2-bringing-the-long-awaited-daw-s-update-closer-to-stable/)).

REAPER is not open source, but at $60 for personal use it is the most automatable DAW on Windows ([reaper.fm](https://www.reaper.fm/purchase.php)). **TwelveTake's `reaper-mcp` (MIT) exposes roughly 179 tools, including loudness, true-peak, spectrum and stereo measurement, over a file-mailbox transport that needs no open ports**, and installs its Lua bridge with a one-command `--install-bridge` on Windows ([TwelveTake-Studios/reaper-mcp](https://github.com/TwelveTake-Studios/reaper-mcp)). The bonfire-systems/itsuzef server (MIT, 60 tools) adds `apply_mastering_chain`, `apply_limiter`, `normalize_project` and six analysis tools via python-reapy ([itsuzef/reaper-mcp](https://github.com/itsuzef/reaper-mcp)). REAPER also buffers everything played on an instrument track for retroactive retrieval, which covers the "I wasn't recording" case for MIDI ([Yamaha Musicians forum](https://yamahamusicians.com/forum/viewtopic.php?p=108256)). Ableton Live has the most popular MCP server (ahujasid/ableton-mcp, MIT, 3.2k stars) and its extended fork, but Live itself costs €209–€444 and brings nothing to this workflow the REAPER servers lack ([ahujasid/ableton-mcp](https://github.com/ahujasid/ableton-mcp); [Bonedo](https://www.bonedo.de/?p=1377828)). The honest recommendation is REAPER for the daily driver with Ardour as the fully-FOSS alternative; the two REAPER servers' measurement tools are the feature that lets an agent actually close the loop on mix decisions, and nothing in Ardour's MCP surface matches them yet.

Capture itself has two viable architectures, and the choice depends on whether per-track separation matters more than standalone feel. Architecture A keeps the MPC standalone: its 1/4" outs feed a two-input interface, its 5-pin MIDI Out carries notes and clock, the DAW sits in continuous record, and the result is a stereo jam plus MIDI. Per-track audio then comes after the fact from the MPC's own "export all tracks as audio files", which Akai itself recommends as the project-portability workaround ([Akai MPC3 FAQ](https://support.akaipro.com/en/support/solutions/articles/69000857771-mpc3-faq)). Architecture B runs controller mode with MPC 3 Desktop, now out of beta with 3.10 and loadable as a VST3/AU/AAX plugin, routing multiple plugin outputs into the DAW mixer; this gives per-track stems and PC-side plugins but disables standalone features and moves the processing load to the PC ([Synth Anatomy](https://synthanatomy.com/2026/10/akai-mpc-os-3-10-free-feature-update-for-mpc-standalone-force-mpc-3-desktop.html); [Sound On Sound](https://www.soundonsound.com/reviews/akai-mpc-one)). Because the user's goal is to play, Architecture A is the default and B is the occasional mode for stem-level mixes or Auto Sampler sessions. Whether MPC 3 Desktop is free for existing One owners was not confirmed in the sources and should be checked before relying on B.

Turning a 20-minute jam into a song is where the MPC's own Arrange mode and the PC diverge. MPC 3 replaced sequence-based Song mode with a DAW-style linear arranger with automation across tracks, buses and master, but it is not externally scriptable ([MusicRadar](https://musicradar.com/news/akai-pro-mpc-3-software); [KVR](https://www.kvraudio.com/news-print.php?id=61332)). On the PC, **`allin1` predicts tempo, beats, downbeats and labelled functional segments (intro, verse, chorus, bridge, outro) from a WAV**, giving the agent section boundaries it can turn into DAW markers and region splits via MCP; its Windows install requires PyTorch and NATTEN and was not verified, with MSAF as the classic fallback ([allin1](https://pypi.org/project/allin1); [MSAF](https://msaf.readthedocs.io/)). Round-tripping sequences back to the MPC should use standard MIDI files, which the MPC imports, rather than the Ableton Live Set export, which forum users across the MPC 3 betas describe as "clunky" and prone to missing audio ([Akai MPC One FAQ](https://support.akaipro.com/en/support/solutions/articles/69000816149-akai-pro-mpc-one-frequently-asked-questions); [MPC-Forums](https://www.mpc-forums.com/viewtopic.php?p=1906255)).

## Scripted mixing and mastering works, with one missing piece

Open source covers plugin hosting, effect libraries, measurement and mastering; it does not cover automatic per-stem balance and EQ, and the design has to route around that. **Spotify's Pedalboard (GPL-3.0, 6.4k stars) hosts VST3 effects and instruments from Python on Windows**, so a script can chain plugins over a bounced jam without the DAW ([spotify/pedalboard](https://github.com/spotify/pedalboard); [PyPI pedalboard](https://pypi.org/project/pedalboard/0.9.2)). The free Windows plugin collections worth standardizing on are **Airwindows Consolidated (MIT, roughly 400 effects in one VST3/CLAP, installable via winget)** and **LSP Plugins (LGPL-3.0, full VST3 and CLAP support)**; x42's meters and parametric EQ are free on Linux but sold as paid Windows binaries, so they drop out ([airwin2rack docs](https://git.tdem.in/baconpaul/airwin2rack/blob/main/doc/manualdaw.md); [wingetgui](https://wingetgui.com/apps/Airwindows-AirwindowsConsolidated-DAWPlugin); [lsp-plug.in](https://lsp-plug.in/); [rg42.org FAQ](https://rg42.org/x42/faq)). Within REAPER, the stock ReaEQ/ReaComp and the TwelveTake server's dedicated ReaEQ tools and LUFS/true-peak measurement let the agent apply a change, measure, and iterate, which is the practical substitute for a true auto-mixer ([TwelveTake-Studios/reaper-mcp](https://github.com/TwelveTake-Studios/reaper-mcp)). The nearest open-source helpers are thin: `auto-mix-prep` does gain staging only, `phantom` gives MCP-based EQ advice rather than applying it, and `vcmix` is a young YAML-driven headless host with an `automix` command built around its own plugin chain ([auto-mix-prep](https://pypi.org/project/auto-mix-prep); [phantom](https://cdn.jsdelivr.net/gh/fadelabs/phantom@main/README.md); [vcmix](https://pypi.org/project/vcmix/)).

Mastering is the strongest open-source link. **Matchering 2.0 (GPL-3.0, about 2.7k stars) takes a target and a reference track and matches RMS, frequency response, peak and stereo width, with its own brickwall limiter, as a pip library callable in three lines** ([sergree/matchering](https://github.com/sergree/matchering)). Its quality depends on choosing a reference in the right genre, which is a decision the user or the agent makes once per project. It covers the same job as the cloud masterers, which range from free (BandLab) to roughly $4–6 per track (LANDR, Masterchannel, Waves) to $15–30 per month, none of which expose a local API an agent can drive ([fast.io](https://fast.io/resources/best-ai-mastering-tools-2026/); [Masterchannel blog](https://blog.masterchannel.ai/what-does-it-cost-to-master-a-song/)). On the commercial side, iZotope Neutron 5 ($299, Elements $55) and Ozone 12 (Elements $55 to Advanced $499) are the mainstream AI mix and master assistants, and sonible smart:EQ 4 and smart:limit ($129 each) are the single-knob alternatives; all are Windows VST3 that an agent can insert via MCP, but their "assistant" analysis runs from a button the MCP servers cannot press ([iZotope](https://www.izotope.com/collections/dynamics); [iZotope](https://www.izotope.com/collections/filter); [Plugin Boutique](https://www.pluginboutique.com/manufacturers/190-Sonible)).

## Custom instruments reach the MPC only as multisamples

An AI assistant can genuinely build a VST3 on Windows 11 in 2026, but documented results are modest and the MPC One will never run it directly. The best-evidenced path is Claude Code with JUCE, CMake and Visual Studio 2022: The Audio Programmer's February 2026 experiment produced a working gain plugin with "zero hand-written code", though custom UI work eventually "broke down" and toolchain setup consumed real time ([The Audio Programmer](https://www.theaudioprogrammer.com/content/building-an-audio-plugin-with-claude-code-a-vibe-coding-experiment)). **The MIT-licensed Audio Plugin Coder (APC, JUCE 9, 343 stars, v1.8.0) packages that workflow for Claude Code, Cursor and Codex with a Dream/Plan/Design/Implement/Ship phase structure, a bundled pluginval validator, and VST3/Standalone output on Windows, requiring Git, Node 18+, Python 3.8+, VS2022 C++, CMake 3.22+ and WebView2** ([Noizefield/audio-plugin-coder](https://github.com/Noizefield/audio-plugin-coder); [Noizefield](https://www.noizefield.com/news/create-vst-plugins-with-ai-apc)). For fast DSP prototyping without a compiler, Sound On Sound's January 2026 tutorial used Claude to write a REAPER JSFX sequencer because JSFX is "the most straightforward format and Reaper has a built-in compiler", another point in REAPER's favour, even though per-step velocity never worked ([Sound On Sound](https://www.soundonsound.com/techniques/vibe-coding-how-anyone-can-create-plug-ins)). Faust and Cmajor are higher-level DSL routes (Faust's web IDE compiles without a local toolchain; Cmajor hot-reloads and exports JUCE or CLAP projects), but no public write-up shows an LLM producing a polished polyphonic synth with a custom GUI end to end, so instrument building remains the least-proven leg ([Faust Manual: Tools](https://faustdoc.grame.fr/manual/tools/); [cmajor.dev](https://cmajor.dev/docs/GettingStarted)).

Licensing matters here because the plugin inherits the framework's terms. **JUCE is dual-licensed: AGPLv3, or a Starter tier that is free up to $20,000 revenue; Indie is $40 per user per month up to $300,000** ([JUCE](https://juce.com/get-juce/)). Cmajor is GPLv3 or a commercial licence around GBP 2,000, and every HISE-built instrument must be GPLv3 unless a commercial licence is bought; iPlug2 (zlib-like) and DPF are the permissive alternatives if closed distribution ever matters ([cmajor.dev Licence](https://cmajor.dev/docs/Licence); [HISE docs](https://docs.hise.audio/introduction/index.html); [iPlug2](https://de.github.com/iPlug2/iPlug2)). For a hobbyist distributing nothing, JUCE Starter under APC is fine.

Getting the sound onto the MPC is a sampling problem, and there are two ways to solve it. The official route is Controller Mode, MPC Desktop's Tools > Auto Sampler (note range and stride, velocity layers, note and tail length, looping), then File > Save Current Programs to the SD card, which yields a `.xpm` keygroup plus WAVs that load standalone ([Akai: Auto Sampler](https://support.akaipro.com/en/support/solutions/articles/69000815776-akai-pro-mpc-2-software-how-to-create-keygroup-programs-using-auto-sampler)). The scriptable route replaces that GUI: **Pedalboard loads a VST3 instrument and renders MIDI notes to audio, and DawDreamer (GPL-3.0, Python 3.11–3.14 on Windows) does the same with parameter automation and embedded Faust**, so a script can iterate every third semitone across up to four velocity layers, write WAVs with tails, and hand them to ConvertWithMoss or `mpc-keygroup-builder` for the `.xpm` ([spotify/pedalboard](https://github.com/spotify/pedalboard); [DBraun/DawDreamer](https://github.com/DBraun/DawDreamer)). Two caveats shape the sampling grid: a keygroup holds at most four sample layers and a program at most 128 keygroups, and a Pedalboard issue reports VST parameters resetting to defaults during MIDI rendering, so verify patch state in the rendered audio ([MPC-Forums](https://www.mpc-forums.com/viewtopic.php?p=1876042); [pedalboard issues](https://fr.github.com/spotify/pedalboard/issues)). The same pipeline multisamples existing open-source synths, which is the quickest win: Surge XT (GPL-3.0, with `surgepy` Python bindings for headless rendering), Dexed and Vital all run on Windows ([surge-synthesizer/surge](https://github.com/surge-synthesizer/surge); [mtytel/vital](https://github.com/mtytel/vital)). Since 3.9, simple subtractive, FM or wavetable patches can also be rebuilt natively with MPC Oscillators on a keygroup track, but that is manual parameter transcription, not a file import ([Gearnews](https://www.gearnews.com/akai-mpc-3-synth/)).

## Recommended architecture, licensing caveats and build order

The end-to-end design keeps the MPC One standalone and makes the PC the automation host. On the hardware side, the One's 1/4" outs and 5-pin MIDI Out go into a class-compliant two-input audio interface with MIDI I/O; the SD card is the content bus. On the PC, Claude Code orchestrates three toolsets: a Python "kit factory" (audio-separator, DrumSep, librosa, soundfile, a template-based `.xpm` writer, mpc-preview-builder, SD deploy), a DAW agent (REAPER with TwelveTake's reaper-mcp, or Ardour MCPHttp for a FOSS-only build), and a Python "post" chain (allin1 for sections, Pedalboard with Airwindows/LSP for processing, pyloudnorm-style or MCP loudness checks, Matchering for the master). Controller Mode is reserved for stem-level mixing and Auto Sampler sessions. The table below records the licensing and cost caveats that bear on the choice at each stage.

| Stage | Open-source pick (license) | Caveat | Commercial alternative |
|---|---|---|---|
| Stems | python-audio-separator (MIT), DrumSep (MIT) | DrumSep installer is Linux-first; Demucs archived | MPC Stems $9.99 (drums stem only), UVR5 GUI (free) |
| Chopping | librosa + soundfile (ISC/BSD) | Avoid madmom (CC BY-NC models) and Essentia (AGPL, no Windows wheel) | Serato Sample, Atlas 2 ($99), XO (~$89–149) |
| Program writing | Template-based XML writer; mpc-keygroup-builder (MIT); ConvertWithMoss (LGPL-3.0) | No official XPM schema; reported JSON XPM variant unverified | Kit Creator $59.99, Kit Maker $35 |
| Sound generation | Stable Audio Open Small (Stability Community License) | Confirm the revenue threshold at stability.ai/license; MusicGen is CC-BY-NC | Splice Variations/Craft (commercial-use licensed), ElevenLabs SFX (paid tiers) |
| DAW + agent | Ardour 9 + MCPHttp (GPL, $1 binary) | Experimental server; no loudness tools | REAPER $60 + reaper-mcp (MIT), Ableton €209–444 + ableton-mcp |
| Plugin host / effects | Pedalboard (GPL-3.0), Airwindows (MIT), LSP (LGPL-3.0) | GPL only matters if you redistribute scripts bundling it | Neutron 5 $299, smart:EQ 4 $129 |
| Mastering | Matchering (GPL-3.0) | Needs a good reference track | Ozone 12 $55–499, LANDR ~$4/track |
| Custom VST | APC (MIT) on JUCE (AGPL / Starter free <$20k) | Instruments with custom GUIs remain unproven for LLMs | RNBO (Max 9), Synplant 2 Genopatch €149 |
| VST to MPC | Pedalboard or DawDreamer (GPL-3.0) render, then keygroup `.xpm` | 4 layers per keygroup, 128 keygroups; parameter-reset bug | Akai Auto Sampler (free, GUI) |

Two cross-cutting legal points deserve emphasis. For AI-generated musical material rather than tools, the litigation picture in October 2026 is unsettled: UMG and Sony's suits against Suno remain active with tens of thousands of recordings added mid-2026, Udio disabled all downloads after its UMG deal, GEMA won against Suno in Germany in July 2026, and trackers expect no US fair-use ruling before 2027, so Splice's catalog and tools are the lowest-risk source and free tiers of every generator are non-commercial ([Chartlex tracker](https://www.chartlex.com/blog/business/music-industry-ai-lawsuits-tracker-2026); [Digital Music News](https://www.digitalmusicnews.com/2025/10/31/udio-downloads-disabled-umg-deal/); [Suno Terms](https://suno.com/terms)). For tools, the GPL-3.0 on Pedalboard, DawDreamer and Matchering constrains redistribution of software that links them, not the audio they produce, so a private pipeline is unaffected.

The build order below is prioritized by value delivered per hour and by how much each step de-risks the next. The first three steps produce a usable result in a weekend; the rest layer on.

| Priority | Step | Why first |
|---|---|---|
| 1 | Install Python 3.12 (python.org installer, not the Store), librosa, soundfile, audio-separator, ffmpeg; save a 16-pad drum program from the MPC on 3.10 and copy its `.xpm` to the PC as the template | Confirms the toolchain on Windows and captures the current XPM structure before writing any generator |
| 2 | Have Claude Code write `make_kit.py`: onset-chop a folder of WAVs to trimmed one-shots, fill 16 pads in the template, run mpc-preview-builder, write `Kit.xpm` + WAVs to the SD card; load it on the MPC | The single highest-value automation; also the first test that a generated XML `.xpm` loads on 3.10, which no source has confirmed |
| 3 | Buy or borrow a two-input audio interface with MIDI I/O; patch the One's 1/4" outs and 5-pin MIDI Out; install REAPER (60-day trial) and TwelveTake reaper-mcp with `--install-bridge`; have the agent arm a track and record a test jam | Establishes the capture path that every later stage depends on; the standalone One cannot send multitrack USB audio |
| 4 | Add stems: audio-separator to a drum stem, then DrumSep (manual Demucs install or WSL2) into `make_kit.py`; evaluate MPC Stems ($9.99) for on-device loop work | Extends kit sources from one-shots to any record or loop |
| 5 | Add the post chain: allin1 (verify NATTEN installs on Windows) to propose section markers via MCP; Pedalboard + Airwindows/LSP for bus processing; Matchering against a chosen reference | Turns a recorded jam into a finished track without touching the DAW GUI |
| 6 | Keygroup pipeline: Pedalboard renders Surge XT or Dexed patches across the key range; ConvertWithMoss or mpc-keygroup-builder writes the keygroup `.xpm`; compare against Akai Auto Sampler output once | Proves the multisample route with known synths before trusting it with custom ones |
| 7 | Custom instruments: scaffold APC with Claude Code, build a simple VST3 effect first, then an instrument; feed it through step 6 | Lowest proven success rate; only after the rest works |
| 8 | Optional: Carabiner for Ableton Link, Ardour 9 as a FOSS DAW track, Stable Audio Open Small for generated one-shots | Nice-to-haves that each add a dependency or licence check |

## Conclusion

The research reframes the question. "Connect the MPC to a DAW and let AI run it" sounds like an integration problem, but the MPC One's closed firmware turns it into a content-and-capture problem: the AI never touches the MPC, it only prepares what goes onto the SD card and processes what comes out of the jacks. That is a feature rather than a limitation, because it means the "just play" experience is untouched by any software instability on the PC side, and it means the whole PC toolchain can be swapped or upgraded without re-learning the instrument. The open-source gap is small and specific: a tested XPM writer for MPC 3.10 and a Windows-friendly DrumSep install are the only components that have to be built or wrangled rather than installed, and both are weekend tasks for an agent with a template file in hand.

The strategic implication is that the MPC One's biggest weakness, 2 GB of RAM and no plugin hosting, matters far less in this architecture than the spec sheet suggests. Heavy work (separation, synthesis, mixing, mastering) happens on the PC where it belongs; the MPC receives lean, pre-trimmed kits and keygroups it can hold comfortably. The one open question that should be settled empirically before investing further is whether a script-generated classic-XML `.xpm` loads on 3.10 given the reported JSON variant; a positive answer unlocks everything else, and a negative one simply redirects the writer at the format MPCTK already handles.
